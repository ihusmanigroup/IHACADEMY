1. Non-negotiable objective
• Replace the old internship assignment implementation completely with a Winter Internship 2026-27 system.
• Do not append the new data beside old summer/eight-week data. Remove obsolete seed data, static arrays,
mock cards, routes and UI text that can cause duplicates.
• Five tracks only: Frontend Engineering, Backend Engineering, Full Stack Software Engineering, Machine
Learning, Agentic AI Engineering.
• Each track has exactly 4 weeks. Every week has exactly 4 assignments. Week 1 has 2 required free courses;
Weeks 2-4 have 1 required free course each.
• An intern must see only the track selected/approved during application. Never show assignments from other
tracks.
2. Required repository audit before coding
• Inspect package.json files, routing, state management, API layer, database/schema, seed scripts, auth, role
guards, file upload provider and existing internship components.
• Search globally for summer, 8 weeks, Week 5-8, old assignment titles, hardcoded counts, old seed IDs and
obsolete routes.
• Create a short internal migration plan before editing. Do not guess filenames or replace stable infrastructure
unnecessarily.
• Keep the current visual language: white surfaces, blue/cyan primary actions, subtle borders/shadows,
compact dashboard layout and existing dark-mode behavior. Fix contrast issues on assignment detail pages.
3. Data model
• InternshipSeason: id, name, slug, type=winter, year, applicationOpenAt, applicationCloseAt,
programStartAt, programEndAt, status, isActive.
• InternshipTrack: id, seasonId, name, slug, description, icon, order, isActive.
• InternshipEnrollment: userId, seasonId, trackId, status, currentWeek, joinedAt, completedAt. Enforce one
active track per season.
• InternshipWeek: id, trackId, weekNumber 1-4, title, description, unlockRule, order. Add unique(trackId,
weekNumber).
• Assignment: id, weekId, title, slug, difficulty, estimatedHours, question, requirements[], deliverables[],
submissionMode, acceptanceCriteria, evidenceRequired, order, isRequired=true. Add unique(weekId, slug).
• CourseRequirement: id, weekId, courseId or courseSlug, title, required=true, order. Week 1 has two records;
Weeks 2-4 one each.
• CourseProof: enrollmentId, courseRequirementId, fileUrl, fileName, status, mentorFeedback, submittedAt,
reviewedAt, reviewedBy.
• AssignmentSubmission: enrollmentId, assignmentId, githubUrl, liveUrl, notes, attachmentUrl,
attachmentName, status=draft|submitted|changes_requested|approved, mentorFeedback, submittedAt,
reviewedAt, reviewedBy. Add unique(enrollmentId, assignmentId).

5. Backend/API behavior
• GET active internship season and five tracks.
• Application flow creates/selects one track. Once approved/enrolled, track changes require admin action.
• GET intern portal overview returns enrollment, selected track, weeks, progress and lock state.
• GET assignments returns only selected-track records. Server must reject cross-track assignment IDs even if
manually requested.
• GET assignment detail returns full question, requirements, deliverables, submission requirements, prior
submission and mentor feedback.
• POST/PATCH submission validates URLs, notes and attachment type/size. PDF should be supported; optional
image or ZIP support only if existing policy permits.
• POST course proof validates a PDF certificate.
• Mentor/admin review endpoints set approved or changes_requested with feedback.
• Unlock Week 1 immediately after enrollment. Unlock Week N only when all four assignments and all course
proofs in Week N-1 are Approved. Submitted alone is not completion.
• Return consistent error objects and protect all routes with authentication and RBAC.

may remain as a closed/future card only if product requirements still need it; it must not connect to the active

show a track not present in the new dataset.
• Intern portal sidebar: Overview, Assignments, Submissions, Progress, Certificate and LOR if already
supported.
• Assignments page: show four week tabs only. Remove Week 5-8 and Capstone tabs from the old
implementation.
• Each week section shows required free course cards/certificate upload plus exactly four assignment cards.
• Assignment card shows type, track, difficulty, estimated hours, due date/status and Submit Solution.
• Assignment detail route must show the complete question. Do not use one repeated generic sentence for
every assignment. Render requirement checklist, deliverables, acceptance criteria and submission panel.
• Submission panel: GitHub URL, live/deployed URL when applicable, notes/comments, drag-and-drop PDF
upload, declaration checkbox and submit/update button. Validate clearly.
